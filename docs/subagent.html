Subagent 插件说明

本插件把委派任务交给独立启动的 pi 子进程执行。子代理拥有独立的对话上下文，但与主代理共享文件系统和项目目录。它可以在前台运行（主代理等待结果），也可以在后台运行（完成后自动把结果送回主代理）。每次运行都会保存完整会话，运行期间可以在输入框下方选中查看或停止。

插件：extensions/subagent/ 已检查 Pi：0.87.1 入口：index.ts 会话目录：~/.pi/agent/subagent-sessions/

先说结论

1

三种模式，前台或后台

单个（single）、并行（parallel）、链式（chain）。默认在前台运行；加上 async: true 改为后台运行，完成后自动送回结果。

2

每次运行都有完整记录

子进程的会话保存为 Pi 原生会话文件，另存一份元数据。/subagent-history 可以随时查看，重启 Pi 后也在。

3

运行中可以选中、查看、停止

输入框为空时按 ↓ 进入输入框下方的列表，回车看实时进度，连按两次 x 停止，Esc 回到输入框。

当前仓库中的角色

仓库的 extensions/subagent/agents/*.md 是安装源；执行 ./install.sh 后复制到 ~/.pi/agent/agents/，插件运行时从那里发现角色。

角色用途工具仓库默认模型
scout快速侦察代码库，返回压缩后的上下文read, grep, find, ls, bashopenai-codex/gpt-5.6-luna
planner根据上下文和需求制定实现计划read, grep, find, lsopenai-codex/gpt-5.6-sol
reviewer代码审查，关注质量与安全read, grep, find, ls, bashopenai-codex/gpt-5.6-sol
worker通用子代理，完整能力全部默认工具openai-codex/gpt-5.6-sol

“只读”是角色提示词和工具配置上的约束，不是操作系统沙箱。项目级角色（.pi/agents/）只在 agentScope 为 "project" 或 "both" 时使用，并且运行前一定会先确认。

调用方式

模式参数行为
单个{ agent, task }一个角色执行一个任务
并行{ tasks: [...] }最多 8 个任务，同时最多 4 个
链式{ chain: [...] }依次执行，{previous} 替换为上一步答案；任一步失败或被停止就结束
  • 前台（同步）：主代理等待，工具行实时显示每个子代理的当前动作、耗时和输出 token。
  • 后台（异步）：加 async: true，工具立即返回任务 ID。完成后结果以 steer 方式送回：主代理忙时在下一次模型调用前收到，空闲时自动开始新的回复。最多同时 4 个后台任务，需要 TUI 或 RPC 会话。

运行中的交互

只要有子代理在运行，输入框下方就会列出它们：

按键位置作用
↓空的输入框进入列表
↑ ↓列表选择；在第一项按 ↑ 回到输入框
Enter列表打开实时对话记录（任务、思考、工具调用、结果、流式答案）
x x列表或对话记录停止选中的子代理（3 秒内按两次）
Esc列表回到输入框，不会中断主代理
其他键列表回到输入框并正常输入
停止只影响这一个子代理：并行中的其他任务继续，链式在这一步结束，主代理收到“已被用户停止”的结果。已经做出的改动不会回滚。

端到端执行逻辑

主代理调用
subagent 工具
→
校验模式、角色
与项目角色确认
→
启动 pi 子进程
并保存会话
→
解析 JSON 事件
刷新工具行与面板
→
写入元数据
返回或送回结果
  1. 子进程参数为 --mode json -p --session-dir <目录> --session-id <运行 ID> --name …，以及角色的模型、思考级别、工具和追加系统提示词。
  2. 子进程输出的 message_*、tool_execution_* 等事件实时更新当前动作、用量和对话记录。
  3. 运行开始和结束时各写一次 <运行 ID>.meta.json；子会话文件由子进程自己边运行边写入。

历史记录与存储

~/.pi/agent/subagent-sessions/<主会话 ID>/
├── <时间戳>_<运行 ID>.jsonl   # 子会话
└── <运行 ID>.meta.json        # 角色、任务、模式、状态、时间、用量、答案
  • /subagent-history 列出当前会话的全部运行（包括重启前的），回车查看完整记录。
  • 文件永久保留，需要时手动删除目录。它们包含子代理读过的内容，不会出现在 /resume 列表里。
  • Pi 在运行结束前退出时，记录显示为“中断”；后台任务不会在重启后继续。

模型：能否选择，以及怎样选择

可以。运行 /subagent，依次选择用户角色、当前可用的模型和该模型支持的思考级别，结果写回角色文件的 model 与 thinkingLevel，下一次运行即生效。

  • 没有设置 model 的角色继承主代理的模型和思考级别。
  • 设置了 model 的角色保留自己的思考级别，不继承主代理的。
  • 重新运行安装脚本会用仓库里的角色文件覆盖已安装的，长期修改请写进仓库。

常见问题

子代理和主代理隔离了什么？

只隔离对话上下文。文件系统、项目目录和凭据都是共享的；子进程会加载你的用户扩展。

停止子代理会撤销它的改动吗？

不会。停止只是结束进程，已经写入的文件保持原样。

为什么按 ↓ 没反应？

只有在没有子代理运行时，或输入框里已经有文字时才会这样。输入框非空时，↓ 留给编辑器自己使用。

手动测试时怎么只加载这个插件？

使用 pi --no-extensions -e ./extensions/subagent/index.ts。直接传目录的话，因为目录里有 prompts/，Pi 会把它当成资源包，只加载提示词。
